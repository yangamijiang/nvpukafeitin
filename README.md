# 木漏れ日 · Komorebi Maid Café

日系二次元女仆咖啡厅网站，包含用户注册登录与管理员内容管理。前端使用 Vite 和原生 JavaScript，后端使用 Node.js 24、Express 与 SQLite。

## 功能

- 游客可浏览；用户可使用昵称、邮箱与密码注册、登录、退出，刷新后保持登录。
- 管理员可编辑首页、店铺故事、营业说明、4 款菜单的文字/价格、2 位女仆的介绍、2 条活动消息。
- 编辑草稿可在网站中预览；只有点击「保存并发布」才写入数据库，对所有访客生效。
- 内容版本校验防止多个编辑者相互覆盖；已有未保存修改时离开会提醒。
- 密码使用随机盐与 scrypt 哈希，登录使用 HttpOnly Cookie，服务端验证管理员角色，写入使用 CSRF 校验与来源检查。
- 注册不会授予管理员权限；管理员通过一次性初始化密钥设置。
- 预约仍为原有前端演示，不是实际订单。邮箱当前用作登录标识，尚未接入邮箱验证或邮件找回密码。

## 本地开发

需要 Node.js 24+。运行：

```sh
npm ci --cache /tmp/npm-cache
npm run dev
```

该命令启动前端 5173 端口与后端 3000 端口，Vite 将 `/api` 请求转发到后端。数据库默认存放在 `.local/komorebi.sqlite`，已加入 Git 忽略规则。

## 首次创建管理员

1. 本地首次启动时，系统会在 `.local/admin-setup-key` 生成随机密钥（文件权限 0600）。仅网站部署者可读取，不会通过网页接口提供，也不会写入日志。
2. 打开网站的「登录 / 注册」→「首次设置管理员」。
3. 输入该密钥以及管理员昵称、邮箱、至少 10 位的密码。
4. 成功后自动登录并打开内容管理。初始化接口永久关闭；本地密钥文件被删除。不要将密钥或密码提交 Git。

托管环境可用安全环境变量 `ADMIN_SETUP_KEY` 指定初始化密钥。管理员创建成功后应删除托管平台上的该变量。不要把它设置为 `VITE_` 开头的变量，也不要放入前端代码。

## 构建与验证

```sh
npm run build
npm run test:api
npm test
```

浏览器测试使用 `/usr/bin/chromium`，可通过 `CHROMIUM_PATH` 指定其他路径。测试数据库与管理员账号位于独立的临时目录，不会修改实际开发数据库。测试后可删除 `/tmp/komorebi-e2e-*` 临时目录。

生产服务器使用 `npm start` 同时提供 `dist` 中的前端与 `/api`。`npm run preview` 仅提供静态预览，不包含账号服务。

## 正式部署

**GitHub Pages 无法运行账号数据库和管理接口。请将整个项目部署到支持 Node.js 或 Docker 的服务上。** 仅上传 `dist` 仍只能浏览静态网页，登录会明确提示服务未上线。

1. 构建命令：`npm ci && npm run build`；启动命令：`npm start`。
2. 设置 `NODE_ENV=production` 与 `APP_ORIGIN=https://实际网站域名`（不要带末尾斜杠）。必须使用 HTTPS；生产模式会启用 Secure Cookie。
3. 将 `DATABASE_PATH` 指向**持久化磁盘**上的文件。单实例运行；不要使用无状态函数或多副本共享本地 SQLite。重新部署后必须保留该磁盘，否则账号和编辑内容会丢失。
4. 在平台安全设置中生成随机 `ADMIN_SETUP_KEY`。完成一次性管理员设置后删除该变量。
5. 如果服务位于一层可信反向代理后面，设置 `TRUST_PROXY=1`；否则不要设置。
6. 健康检查路径：`/api/health`。上线后测试注册、登录、管理员发布，以及重启后的数据保留。

包含 `Dockerfile` 和 Render Blueprint `render.yaml`。Render 配置使用付费 Starter 服务及 1 GB 持久化磁盘，部署前查看平台价格；本项目没有自动购买或创建云服务。使用 Render 时先获取服务的 HTTPS 域名，再将其填入 `APP_ORIGIN`，然后重部署。`ADMIN_SETUP_KEY` 由 Render 自动生成，可在该服务的环境变量设置中安全查看，用于首次设置管理员。

上线前请备份持久化数据库并妥善保护备份，其中包含账号与密码哈希。部署者可在服务器恢复管理员访问，当前不提供邮件密码重置功能。

## 素材与内容
